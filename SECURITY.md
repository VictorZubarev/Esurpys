# Security Policy

## 1. Purpose

Security is an important consideration in the development of Esurpys.

This document describes the project's initial approach to identifying, reporting, and addressing potential security vulnerabilities.

## 2. Supported Versions

Esurpys is currently under development.

A formal version support policy has not yet been established. Supported versions and security maintenance periods will be documented as releases become available.

## 3. Reporting a Vulnerability

If you discover a potential security vulnerability, please avoid publishing exploit details or sensitive information in a public issue.

Until a dedicated security contact is established, you may use GitHub's private vulnerability reporting feature if it is enabled for this repository.

If private reporting is unavailable, please open a minimal public issue requesting a private reporting channel without including exploit details, credentials, personal data, or other sensitive information.

## 4. What to Include

When reporting a vulnerability through an appropriate private channel, include:

- A concise description of the issue.
- The affected component or version, if known.
- Steps to reproduce the issue.
- The potential security impact.
- Relevant logs or proof-of-concept material, with sensitive data removed.

Please report only information that you are authorized to access and test.

## 5. Response and Remediation

Reports will be reviewed as project resources permit.

If a vulnerability is confirmed, remediation may include a code fix, configuration change, documentation update, or release containing the correction.

Response times and coordinated disclosure procedures have not yet been formally established. They will be documented when a dedicated security process is introduced.

## 6. Security Best Practices

Contributors should:

- Never commit passwords, API keys, access tokens, or private keys.
- Validate untrusted input.
- Apply appropriate access controls.
- Minimize collection and retention of personal data.
- Keep dependencies reasonably up to date.
- Review changes for security implications.
- Avoid publishing sensitive information in issues, commits, logs, or documentation.

## 7. Scope and Limitations

This policy describes the project's initial security intentions. It does not constitute a guarantee that Esurpys is free from vulnerabilities or that every report will receive a particular response time.

## 8. Updates

This policy will evolve as the project matures and formal security procedures are established.
