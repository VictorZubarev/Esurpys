# Contributing to Esurpys

## 1. Purpose

This document describes the process and principles for contributing to Esurpys.

The goal is to maintain a transparent, collaborative, and maintainable development process as the project evolves.

## 2. Current Project Status

Esurpys is under development. Contribution procedures may evolve as the project structure, technology stack, and development workflow become more established.

Please review the repository README and relevant documentation before proposing changes.

## 3. Types of Contributions

Potential contributions include:

- Bug reports and reproducible issue descriptions.
- Feature suggestions.
- Documentation improvements.
- Code contributions.
- Tests and quality improvements.
- Accessibility and usability improvements.
- Technical research and evaluation.

The suitability of a contribution depends on the project's current needs and scope.

## 4. Reporting Issues

When reporting an issue, please include as much relevant information as possible:

- A clear description of the problem.
- Steps to reproduce the issue.
- Expected behavior.
- Actual behavior.
- Relevant error messages or logs, with secrets and personal information removed.
- Environment details when they are relevant.

Please check existing issues before opening a duplicate report.

## 5. Proposing Changes

Before making a substantial change, consider opening an issue to discuss the proposed approach.

Pull requests should:

- Explain the problem being addressed.
- Describe the proposed solution.
- Keep changes focused and reviewable.
- Include tests when appropriate.
- Update relevant documentation.
- Identify known limitations or risks.

## 6. Code Quality

Contributions should prioritize:

- Readability and maintainability.
- Clear naming and consistent formatting.
- Appropriate error handling.
- Security and privacy.
- Testing of important behavior.
- Avoidance of unnecessary complexity.

Project-specific conventions will be documented as the codebase develops.

## 7. Security and Privacy

Do not include passwords, access tokens, private keys, personal information, or other sensitive data in issues, commits, logs, or pull requests.

Please do not publicly disclose suspected security vulnerabilities. Follow the instructions in `SECURITY.md` once a security reporting process has been established.

## 8. Review Process

Contributions may be reviewed for correctness, maintainability, security, scope, and alignment with project goals.

Submitting a contribution does not guarantee acceptance or inclusion in a release.

## 9. Attribution

Contributions should be accurately attributed to the people who performed the work.

Contributors should not claim work, credentials, affiliations, or results that they cannot substantiate.

## 10. Updates

This document will be updated as Esurpys adopts more specific development practices and collaboration workflows.
